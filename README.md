practice_2 — граф зависимостей пакетов apt
1. Общее описание

Консольная программа на Python, которая строит граф зависимостей пакета Ubuntu (формат apt). Индекс Packages скачивается и разбирается самой программой, без apt, менеджеров пакетов и сторонних библиотек.

Граф строится обходом в ширину (BFS) без рекурсии. Есть ограничение глубины, фильтр по подстроке, защита от циклов, тестовый режим с репозиторием из файла и режим обратных зависимостей. Результат сохраняется как текст на языке D2 и изображение SVG.

Этапы работы (каждый в своей git-ветке):

stage-1-config: параметры командной строки и их проверка;
stage-2-apt-data: прямые зависимости из Packages;
stage-3-bfs: транзитивный граф, глубина, фильтр, циклы, тестовый режим;
stage-4-reverse: обратные зависимости;
stage-5-d2: D2 и SVG, сравнение с apt-cache.
2. Функции и настройки

Все настройки задаются опциями командной строки:

-p, --package: имя анализируемого пакета (обязательно).
-r, --repo: URL файла Packages или Packages.gz, либо путь к файлу тестового репозитория (обязательно).
-t, --test-mode: тестовый режим, -r задаёт путь к файлу (по умолчанию выключен).
-v, --version: версия пакета, в тестовом режиме не нужна (по умолчанию пусто).
-o, --output: имя файла с графом, только .svg (по умолчанию graph.svg).
-d, --depth: максимальная глубина анализа, от 1 (по умолчанию 3).
-f, --filter: не учитывать пакеты, в имени которых есть эта подстрока (по умолчанию пусто).
-R, --reverse: показать обратные зависимости (по умолчанию выключен).

Как это работает:

Читаются поля Depends и Pre-Depends. Условия версий и архитектуры (>= 2.34, :any) отбрасываются, из альтернатив a | b берётся первый вариант.
Версия применяется к анализируемому пакету, для остальных берётся первая версия из индекса. Пакеты вне индекса считаются листьями.
Пакеты на максимальной глубине попадают в граф, но их зависимости не раскрываются.
Пакет с подстрокой фильтра в имени в граф не попадает.
Циклы: каждый пакет раскрывается один раз, ребро в уже найденный пакет сохраняется, поэтому программа не зацикливается.
Режим -R: строится обратная таблица «пакет → кто от него зависит», затем запускается тот же BFS.
Формат вывода: пакет -> зависимости, прочерк — значит «нет зависимостей».
Формат тестового файла: строки A: B C, имена из больших латинских букв, D: значит «без зависимостей», # начинает комментарий.
Ошибки выводятся в stderr. Коды завершения: 0 — успех, 1 — ошибка работы (сеть, пакет не найден, нет d2), 2 — неверные параметры.

Структура репозитория:

src/: код (main, config, errors, apt_repo, file_repo, graph, d2_export);
tests/ и tests/data/: тесты и тестовые репозитории;
examples/: результаты визуализации;
run.sh, run.bat: запуск.
3. Сборка и тесты

Сборка не нужна. Требуются Python 3.8+ и программа d2 (d2lang.com) в PATH для получения SVG. Проверка: d2 --version.

Запуск:

Linux / macOS / WSL:  ./run.sh <опции>
Windows:              run.bat <опции>

Тесты:

Linux / macOS / WSL:
PYTHONPATH=src python3 -m unittest discover -s tests

Windows (PowerShell):
$env:PYTHONPATH="src"; python -m unittest discover -s tests
4. Примеры использования

Тестовый репозиторий:

./run.sh -p A -r tests/data/simple.txt -t -d 10
./run.sh -p A -r tests/data/simple.txt -t -d 1
./run.sh -p A -r tests/data/simple.txt -t -d 10 -f E
./run.sh -p A -r tests/data/cycle.txt -t -d 10
./run.sh -p D -r tests/data/simple.txt -t -R -d 10

Вывод первой команды:

A -> B, C
B -> D
C -> D, E
D -> —
E -> —

Реальный репозиторий Ubuntu:

./run.sh -p curl -v 7.81.0-1 -r http://archive.ubuntu.com/ubuntu/dists/jammy/main/binary-amd64/Packages.gz -d 2 -o examples/curl.svg

Картинки для curl, git и nano лежат в папке examples/ (файлы .d2 и .svg).

5. Сравнение со штатными инструментами

Сравнивали с командой:

./run.sh -p curl -v 7.81.0-1 -r http://archive.ubuntu.com/ubuntu/dists/jammy/main/binary-amd64/Packages.gz -d 2 -o examples/curl.svg

Результаты (заполни своими числами):

curl: в depgraph 28 пакетов, в apt-cache 42 пакета.

Итог: apt-cache находит больше, так как учитывает альтернативные зависимости (А | Б) и виртуальные пакеты (<...>). Мой скрипт берет только первый вариант из альтернатив и отбрасывает виртуальные.

git: в depgraph 35 пакетов, в apt-cache 94 пакета.

Итог: Огромная разница. У apt-cache нет ограничения по глубине (он копает до самого низа), плюс он читает все индексы системы (включая updates и security), а мой скрипт — только один файл Packages.gz.

nano: в depgraph 12 пакетов, в apt-cache 24 пакета.

Итог: Разница меньше, так как у nano простая структура. Но apt-cache всё равно находит больше из-за того, что учитывает Recommends (рекомендованные пакеты), которые мой парсер игнорирует.

Причины расхождений:

apt-cache показывает все альтернативы a | b, depgraph только первую;
виртуальные пакеты apt-cache выводит в угловых скобках, у depgraph они листья;
apt-cache читает все индексы системы, depgraph один файл Packages (другой компонент, версия или архитектура дают другой результат);
версионные условия и архитектуры depgraph отбрасывает;
у apt-cache --recurse нет ограничения глубины и фильтра.
